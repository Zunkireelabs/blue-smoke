1 · As-built — the gate

selectStack(), src/app/navigation.tsx:76-96. Five mutually exclusive navigators. A route not in the mounted stack does not exist, so every transition between these boxes is implicit — driven by state, never by a screen.

🔴 The trap. A declined user sits on verify while sessionStatus is still signedIn, so the auth stack is not mounted. That stack holds one screen, with no sign-out, no support and — per DE-7 — no working retry. There is no exit. Force-quitting and relaunching restores the identical state from the Keychain. Resolved by F6.Z.

2 · As-built — auth, and its 6 dead ends

Every navigation call in the entire app is on this diagram. Six, all of them a user tapping a link between two forms. There are zero calls to replace, reset, goBack or push anywhere in src/.

3 · As-built — why verification never lands

Four lanes. The hatched one is Persona’s SDK, running in its own process — we design nothing inside it. Follow the chain: nothing the user does can ever write a row.

4 · F1 — Onboarding & permission priming

unbuilt P1-2.0, 0/9. The rule that shapes it: permissions are requested at the moment of need, never at launch.

5 · F2 — Signup with email

Resolves DE-1 DE-2.

Success states should not be screens. DE-2 renders “Account created / You’re signed in” and then relies on onAuthStateChange to move the user. When the listener fires, the panel is a pointless flash; when it does not, the user is stuck forever. Either navigate explicitly, or render nothing and let the gate move them. Same fix for DE-3 and DE-4.

8 · F6 — Age verification

Resolves DE-7 DE-8 SD-3 and the trap. The hatched lane is Persona’s.

🔴 min_age is upstream of this entire diagram. Persona returns approved meaning “passed the checks the template was configured with” — not “is over 18”. A template with no age requirement approves a 14-year-old, and every control below still functions perfectly while the product’s core promise silently fails. No code we write can detect this. A screenshot of the template’s age setting closes it.

9 · F7 — Pair a device

blocked No UI exists. BLE lower layers are built and tested; connection.ts, commands.ts and proximity.ts throw.

🔴 OQ-12 — the serial_hash salt. F7.9 cannot run without it, and a guessed salt fails silently: the hash is well-formed, the lookup misses, and the failure looks like a hardware fault. Do not invent one.

10 · F8 — Lock & unlock

State names are spec §7.3, verbatim. Thresholds are §7.2 and must not be re-derived.

The firmware dead-man timer locks the device, not the app. The app’s proximity monitor is advisory — it makes locking feel fast. If the app is killed, backgrounded, crashed, or the battery dies, safety is unaffected. No screen may imply the app must be running for the device to be safe.
