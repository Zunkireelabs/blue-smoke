# Execution brief — the app does not boot: Metro bundle failure + the CI gap that hid it

**Base:** `chore/integrate-auth-db-persona` @ `eea907f`
**Severity:** blocking. The native build succeeds and the app installs and launches, then dies on
the JS bundle. **No one has ever run this app.** 42 commits, 222 passing tests, green CI.

## What happens

`npm run ios` builds and launches. The app immediately shows a red-box Babel error and renders
nothing:

```
node_modules/zod/v4/classic/external.js: Export namespace should be first transformed by
`@babel/plugin-transform-export-namespace-from`.
> 1 | export * as core from "../core/index.js";
```

Reproducible headlessly, without the simulator:

```
npx react-native bundle --platform ios --dev true --entry-file index.js --bundle-output /tmp/t.bundle
```

## Why no test caught it — read this, it is the actual lesson

This is **not** a false-green test. It is a blind spot no Jest test could have covered.

`zod@4.4.3` ships dual builds and its `exports` map splits by condition:

```
"require": "./index.cjs"   ← Jest resolves this. CommonJS. No `export * as` syntax exists in it.
"import":  "./index.js"    ← Metro resolves this. Contains `export * as core from ...`.
```

Verified: `require.resolve('zod')` returns `.../zod/index.cjs`. So the entire test suite exercises
a build of zod that never contains the syntax that breaks the bundler. Adding more unit tests
would not have found this and will not prevent the next one.

`.github/workflows/ci.yml` runs `typecheck`, `lint`, `test` — **none of which invoke Metro.** The
only thing that can catch this class of defect is actually bundling.

## Required change 1 — make it bundle

Add `@babel/plugin-transform-export-namespace-from` to the `plugins` array in `babel.config.js`.
Put it first, before `module-resolver`.

**Verified working before this brief was written:** with that one line added, the same bundle
command succeeds and writes a 7.8 MB bundle. The change was then reverted, so you are applying it
fresh.

Do not restructure `babel.config.js` otherwise. Its `loadDotEnv()` block and the
`transform-inline-environment-variables` plugin are load-bearing and documented in place — leave
both alone.

## Required change 2 — the dependency is currently transitive

`@babel/plugin-transform-export-namespace-from@7.29.7` resolves today only because something else
pulled it in. Nothing in `package.json` requires it, so a lockfile regeneration can drop it and
break the build again with no diff to explain why.

Add it as an explicit **devDependency** at the installed version.

`package.json` is a contested shared file (CLAUDE.md) — note the addition in your report so it can
be announced. Do not hand-resolve any lockfile conflict; if one appears, stop and report.

## Required change 3 — close the CI gap

Add an `npm run bundle:check` script that runs the Metro bundle for **both** platforms to a temp
output, and wire it into `.github/workflows/ci.yml`'s `verify` job after `Test`.

This is the part that matters more than the zod fix. Any future dependency that ships ESM-only
syntax, any Babel/Metro config regression, any bad `module-resolver` alias — none of it is visible
to typecheck, lint, or Jest. A bundle step is the only gate that sees what the app actually loads.

Keep it fast: `--dev true`, no minification, discard the output.
