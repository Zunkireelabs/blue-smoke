## Why this shape

other wrong response is to hardcode a guess into 11 screens and repaint them by hand later.

So: **every visual value lives in one token module, and components consume tokens only.** When
brand assets land, the reskin is an edit to `tokens.ts` and nothing else. That property is the
actual deliverable of this task — more than any particular colour. It is enforced by a guard
test (below), not by good intentions.

`devices/HomeScreen.tsx` and `verification/PersonaVerificationScreen.tsx`. This is a design pass

## Tokens

Semantic names, not literal ones: `color.textPrimary`, not `color.grey900`. A literal name
re-teaches the whole codebase the brand when the brand changes, which is the failure this task
exists to prevent.

Ship a **provisional** neutral palette. Mark it in the file header, in one sentence, as
provisional pending OQ-7 with the reskin path stated. Do not invent a brand identity — no logo,
no brand colour guesses presented as decisions.

Structure the token module so a second theme is *possible* without building one. Do not build
dark mode this round.

## Accessibility — the part that is testable, so test it

Per the P0-7.0 checklist:
- **Contrast:** every foreground/background token pair the components actually use must meet
  WCAG AA (4.5:1 body, 3:1 large text). Compute the ratio in a test from the token values — do
  not eyeball it and do not assert a hardcoded "expected ratio" number you derived by running the
  code. Write the WCAG formula, feed it the tokens, assert the threshold.
- **Touch targets:** every interactive primitive has a minimum hit area of 44×44 (iOS HIG) /
  48×48dp (Android). Assert it from the component's resolved style.
- **Dynamic type:** text must scale. Do not set `allowFontScaling={false}` anywhere; if a layout
  needs to survive large type, it wraps rather than clips.

## The token-only guard

Mirror the existing pattern in `tools/lint-guard/` (see `__tests__/verificationGuard.test.ts`) —
a test that reads the source of `src/shared/ui/**` and the restyled screens and fails on a
literal colour (`#rrggbb`, `rgb(`, `rgba(`) outside `tokens.ts`.

Make it fail for the right reason: prove it by adding a literal hex to a component, watching it
fail, and reverting. A guard that has never fired is not a guard.

## Testing traps in this codebase — read before writing tests

These have all produced false greens here already:

- **No snapshot tests as the primary assertion.** A snapshot passes by recording whatever the
  component currently does, including wrong. Assert the property you care about — the contrast
  ratio, the resolved min height — not the serialised tree.
- **React Navigation mounts only the FOCUSED screen.** A test that queries for rendered routes
  matches an empty array and passes vacuously. If you assert on rendered output, first assert
  that the thing you are querying is present at all.
- **An assertion over an empty collection always passes.** Any `forEach`/`every` over token pairs
  must first assert the collection is non-empty.
