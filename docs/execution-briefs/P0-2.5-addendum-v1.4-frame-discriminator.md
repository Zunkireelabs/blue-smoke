## 1. What happened, and why it is your finding

Your report flagged six §4 ambiguities rather than guessing silently. **Ambiguity #1 was not an
ambiguity — it was a defect**, and it has been fixed in the spec.

You wrote that `authResponse` carries no frame-index discriminator, so firmware can only track
order by an internal cursor. Correct. The consequence you stopped short of: §4.5 step 4 *mandated*
that "an out-of-order frame resets the handshake" — and with both frames being 20 opaque bytes on
one characteristic, **the device cannot detect an out-of-order frame at all.** The spec required a
behaviour its own wire format made impossible, and a buggy or hostile central could desynchronise
that cursor with no defined recovery.

That is the tenth defect found by re-deriving a section instead of trusting it, and the third in
§4. **Flagging it rather than papering over it is what caused it to be found.** Do the same again.

## 3. The change — exact layouts

### 3.1 Byte layouts

Both frames stay **20 bytes**. Byte 0 of each is now `frameIndex`.

```
frame 1: [ frameIndex = 0x01 (1 B) | session_id (16 B) | keyGeneration (1 B) | reserved (2 B) ]
frame 2: [ frameIndex = 0x02 (1 B) | proof (16 B)      | expiresAtDelta (3 B, uint24 LE sec)  ]
```

Offsets, to remove all doubt:

| Frame | Field | Offset | Length |
|---|---|---:|---:|
| 1 | `frameIndex` (= `0x01`) | 0 | 1 |
| 1 | `sessionId` | 1 | 16 |
| 1 | `keyGeneration` | 17 | 1 |
| 1 | `reserved` | 18 | 2 |
| 2 | `frameIndex` (= `0x02`) | 0 | 1 |
| 2 | `proof` | 1 | 16 |
| 2 | `expiresAtDelta` | 17 | 3 |

**`expiresAtDelta` is now uint24 LE, not uint32.** It narrowed to free byte 0. Max `0xFFFFFF` =
16,777,215 s ≈ 194 days, against the 90-day `SESSION_EXPIRY_MAX_DAYS` cap — 2.1× headroom. Values
above the cap are **clamped, never rejected** (unchanged behaviour, but now explicitly tested).

### 3.2 The proof CMAC changes width, not shape

```
proof = AES-128-CMAC(K_sess, 0x01 ‖ protocolVersion ‖ N ‖ session_id[0..3] ‖ expiresAtDelta)
```

Identical, except `expiresAtDelta` contributes **3 bytes instead of 4**. Total input goes 26 → 25
bytes. HKDF is untouched.

**`frameIndex` is deliberately NOT in the CMAC.** It is framing, not a security parameter — the
proof already binds `N` and `session_id`, and forging `frameIndex` without `K_sess` achieves
nothing beyond a reset. Do not add it.

### 3.3 New obligation F12

> **F12 — `authResponse` frames are validated by `frameIndex`, never by position.** Frame 1 must
> carry `frameIndex = 0x01`, frame 2 `0x02`. A frame whose `frameIndex` is not the one expected
> next — a repeated frame 1, a frame 2 arriving first, or any other value — **discards all pending
> handshake state**; the device then awaits a fresh frame 1. A reset is a **framing** error, not a
> cryptographic one: it does **not** increment the F6 failure counter and does **not** invalidate
> `N`, which continues to expire on its own §4.5 schedule.

**F12 settles two of your six ambiguities.** #1 is resolved outright. #3 is narrowed: a framing
reset is explicitly *not* an auth failure, so it never feeds backoff. Your remaining reading of
#3 — that bad-tag and replayed *commands* share the counter — is unchanged and still yours.

## 4. Scope — do exactly this

### 4.1 `src/features/ble/protocol.ts` — **rewrite is authorised here, exceptionally**

`CLAUDE.md` says append-only, never rewrite an existing entry. **That rule is suspended for
`AUTH_RESPONSE_FRAME_1_LAYOUT` and `AUTH_RESPONSE_FRAME_2_LAYOUT` only.** The rule exists to stop
silent divergence from the spec; here the spec moved and leaving the old offsets in place *is* the
divergence. Rewrite those two, add a frame-index constant, and cite `§4.5 (v1.4)` so the reason is
visible at the call site. **Everything else in the file stays append-only.**

Nothing else in `protocol.ts` changes. `AUTH_HKDF_INFO`, `AUTH_PROOF_FIXED_PREFIX`,
`SESSION_EXPIRY_MAX_DAYS`, all §4.6/§4.7 constants — untouched.

### 4.2 `byteLayout.ts`

Needs uint24 LE read/write. Add alongside the existing helpers; do not repurpose the uint32 ones.

### 4.3 `deviceCore.ts`

- Replace the positional `awaitingFrame` cursor with `frameIndex` validation per F12.
- On an unexpected `frameIndex`: discard pending handshake state, await a fresh frame 1, **do not**
  touch `consecutiveAuthFailures`, **do not** invalidate `N`.
- Proof input uses the 3-byte `expiresAtDelta`.
- Keep the clamp to `SESSION_EXPIRY_MAX_DAYS`.
- **Update the module-doc ambiguity list**: remove #1 (now resolved by F12), narrow #3. Leave #2,
  #4, #5, #6 exactly as they are — they are still open and still feed the OQ-6 walkthrough.

`writeAuthResponseFrame(frame, bytes)` — your explicit test hook — should now be able to write a
*wrong* `frameIndex`, not merely a wrong position. That is the thing under test.

### 4.4 Tests

Add, as the mock-side analogues of the new acceptance tests:

- **FW-19 (a)** frame 2 sent first → discarded, no session opens
- **FW-19 (b)** frame 1 sent twice → first discarded, device still awaits frame 2
- **FW-19 (c)** after either reset, a clean frame 1 → frame 2 sequence **still succeeds without a
  reconnect**, and the reset consumed **no** F6 backoff attempt
- **FW-20** `expiresAtDelta = 0xFFFFFF` clamps to 90 days — not rejected, not honoured

Update existing handshake tests and `harness.ts` for the new layouts. The RFC 4493 CMAC tests are
unaffected — do not touch them.

### 4.5 The declared-dependency fix

`tools/mock-peripheral/babel.config.js` requires **`@babel/plugin-transform-typescript`**, which is
not in `package.json`. It resolves transitively today, so CI passes — but it is a phantom
dependency: an upstream tree reshuffle breaks the entire mock suite with an error that points
nowhere useful. **Add it to `devDependencies`.** (`@babel/preset-env` is already declared.)

### 4.6 `README.md`

Update the framing description and the ambiguity list to match §4.5 v1.4.
