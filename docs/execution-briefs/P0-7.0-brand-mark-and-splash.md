the `navigation.tsx` wiring, `RESTYLED_SCREENS`, and every test and guard are untouched — none of

## 🔴 The structural rule — corrected

The first issue told you: *bars must be `Animated.View`s, never SVG rects*, because
`useNativeDriver: true` does not work on `react-native-svg` props.

**The premise is right; the rule was too narrow.** It only worked because bars are rectangles, and
a flame cannot be a `View`.

The rule that generalises, and the one to build to now:

> **Each animated layer is its own `<Svg>`, inside its own `Animated.View`, with the transform on
> the View.** The native driver animates the View; the SVG inside it never re-renders.

Here that is exactly **two layers**, superimposed:

1. **Outer flame** — static `<Svg>`, never animated
2. **Inner flame** — its own `<Svg>` in an `Animated.View`, breathing

Both layers use the **full `0 0 100 100` viewBox** and are absolutely positioned at identical size,
so registration between them is automatic — do not crop the inner layer's canvas to its bounding
box and then try to position it by hand.

## Geometry — exact, do not improvise

100×100 grid. These two paths feed the RN component, the storyboard PNG, and every icon size.

**Geometry v3** — v2 rendered as a water droplet, not a flame. Both sides were near-identical
convex curves with a gentle tip. v3 has a narrow high neck flaring into a wide low belly, which is
what actually reads as flame. **Verified as a raster at 300px and at 28/40/56/88px before being
written here**, not judged from a browser preview — that is how v2's droplet got through.

The inner flame is the outer scaled 0.46 about `(49, 84)` — it is a literal echo of the
silhouette, which is why it reads as one mark rather than two shapes. Its lowest point is
**y = 88.1**, leaving ~5 units of blue below it at the base. Do not regenerate it by scaling at
runtime; the numbers above are the contract.

**Fill — outer:** vertical linear gradient, `x1=0 y1=0 x2=0 y2=1`

**Fill — inner:** *the colour of the ground behind the mark*, passed in as a prop. White on the

**Placement, identical in the storyboard and `SH-1`:**
- Mark width = **22% of screen width**
- Vertical centre = **48% of screen height**, not 50%
- Ground = flat `#FFFFFF`, not `GradientGround`

## Motion — "Core"

Only the inner layer moves. The outer silhouette is completely static — that is what makes it read
as a flame burning steadily rather than guttering, and it is the whole idea.

| Property | Value |
|---|---|
| `scaleY` | 0.90 → 1.0 |
| `scaleX` | 0.97 → 1.0 |
| Period | 4.6s, `ease-in-out`, alternating, looping forever |
| Origin | **base of the inner flame** — `transformOrigin: '50% 88%'` |
| Driver | `useNativeDriver: true`, mandatory |

RN 0.86 supports the `transformOrigin` style prop directly — use it rather than compensating with
a `translateY`, which is the usual way this ends up subtly wrong.

🔴 **`'50% 88%'`, not `'50% 100%'` — this was a real defect in the last pass.** The
`Animated.View` is `StyleSheet.absoluteFill`, so its box is the **whole 100×100 square**, and
`100%` resolves to grid y=100 — fifteen units *below* the shape. The core then sank as it
breathed instead of being hinged. The inner flame's base is at **y = 88.1**, so the origin is
`88%`. The old code's comment claimed it was at the base, which is exactly why it read as correct.

**Reduced motion is mandatory.** Read `AccessibilityInfo.isReduceMotionEnabled()` and subscribe to
`reduceMotionChanged`. When on, render the rest state and start no animation at all.

## Pillow — the part that is real work

`generate-brand-assets.py` currently draws polygons. The flame is cubic beziers, and **Pillow has
no bezier primitive**, so:

1. **Flatten each path to a polygon** — evaluate the cubics at a fixed step (64 segments per curve
   is ample at 1024px and keeps the output deterministic). Do not use an adaptive subdivision whose
   segment count depends on floating-point comparisons; it will not reproduce byte-identically.
2. **Draw the gradient per-scanline** — interpolate `#22C1F2` → `#1657D0` down the mark's bounding
   box, then mask it with the flattened outer polygon.
3. **Knock out the inner flame** by drawing it in the ground colour, from the same flattening code.
4. **Supersample.** Render at 4× and downsample with `Image.LANCZOS`. Without it, the flame's long
   diagonal edges will alias visibly at `@1x`.

Byte-identical output across two consecutive runs is still a Definition-of-Done item.
